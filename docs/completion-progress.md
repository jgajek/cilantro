The final recovery build passes 1,208 selected tests and all 24 standard corpus gates. All 25 standard reports, nine reports from four additional recursive inputs, and 46 saved-output trials pass structural verification. Matched corpus comparisons retain recovery coverage and extracted payload hashes. These are different validation configurations, not proof of complete unprotection.

## Implemented follow-up

Integer-helper and numeric-table call-site discovery now tolerates intervening no-ops, while refusing branches and exception boundaries entering the argument sequence. Pure integer helpers can expose their known result while retaining the original call when type initialization must still occur. This preserves initialization effects, exceptions, and the original trigger rather than assuming the initializer is inert.

A late integer-helper pass and a subsequent control-flow cleanup consume helpers that only become pure after the earlier cleanup passes. The final full-pipeline Mlfhntkcvb trial recovered 110 helper results, folded 61 additional constant branches, and removed 108 unreachable instructions across 27 methods. It retained removal of 564 protector types. The dispatcher-shaped method count remained 100; the unresolved numeric-table dependency still needs separate work.

### Indexed VM stores

Isolated VM probes now recognize indexed stores as well as loads. A store must transfer the consumed value into one seeded slot across four numeric input sets, then do the same at a second operand index actually used by the program. Changes elsewhere in the observed engine state, static-field writes, changes to retained stack values, ambiguous destinations, and evidence from only one index prevent this classification. Direct transfers and copied value wrappers are covered by synthetic tests; opcode numbers and field names are not hard-coded.

A controlled before/after probe of the previously emitted WindowsManagement assembly identifies opcode 117 as a store into a 15-slot table. This increases identified operations from 2,489 to 2,640 out of 2,971: 151 additional operations. Both versions walk 2,918 operations and report two stack-depth disagreements; both refuse reconstruction at operation 4. These are focused measurements of the saved assembly, without the full pipeline's sharing of other VM program readings, so their absolute counts should not be substituted for the full-pipeline baseline above. Evidence is saved in `artifacts/indexed-store-probe/windowsmanagement-{baseline,final}.json`.

The indexed-store follow-up passes 875 selected tests and all 24 standard corpus gates (13 Reactor 6, nine Reactor 7.5, and two ConfuserEx), with no failed or missing entries. The standard native-stage gate confirms full string and VM-operation coverage is retained; it does not establish an improvement over its own baseline. The focused 151-operation gain is measured on the same assembly with matched before/after probe settings.

The extended analyst trial in `C:/cilantro-verify/review-trials/indexed-store-windowsmanagement` processes the preserved managed stage directly, with the same input hash and 192-million-step declarations as the earlier native child run. ### Preserve domain initialization during string recovery

The broader corpus check exposed an interaction between two string passes. Recording `SetData` correctly prevented early constant folding from erasing a decoder's externally visible initialization, but the later lookup pass still replaced those calls. Qafcakg and Rrdsk consequently moved 152 strings from the constant-folding counter to the lookup counter, without preserving the initialization trigger.

Lookup recovery now examines the initializers of the resolver and its aliases, isolates each measured lookup's effects, and refuses a lookup that writes static state, patches the image, or records runtime effects. When the initializer has effects outside its own type, recovery retains each original call and substitutes its returned value with the recovered literal afterward. This preserves the initialization trigger and its exceptions. Retained resolver types are not declared orphaned by this rewrite.

Both affected payload gates pass. All 153 Qafcakg and 178 Rrdsk string sites remain recovered; each output now conservatively retains three additional runtime types and one dispatcher-shaped method associated with initialization.
