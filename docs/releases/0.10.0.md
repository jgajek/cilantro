# CILantro 0.10.0 — analyst preview

CILantro recovers and simplifies supported protected .NET samples for analysis. This preview adds substantial recovery and readability work, clearer artifact navigation, and explicit validation qualifications. It does not claim complete unprotection.

## Highlights

- Recover supported Reactor method bodies, strings, constants, resources, and embedded assemblies; clean extracted stages with bounded recursive recovery.
- Continue automatically from supported Reactor native-wrapper extraction into managed recovery while preserving the raw extracted bytes.
- Improve control-flow simplification, explicit call targets, numeric/helper folding, VM reconstruction cleanup, conservative protector removal, and readable naming.
- Preserve initializer side effects during loader cleanup and supported integrity-check specialization.
- Provide an offline analyst report with recommended artifacts, parent-child provenance, separate extracted/cleaned copies, and remaining-work summaries.
- Rewrite documentation around analyst workflows and distinguish structural validity from reconstruction agreement. Surface reconstruction disagreements for both the input and recovered children.
- Fix Windows status-file replacement during concurrent polling so a brief reader conflict does not leave a completed run labeled as starting.

## Validation and known limits

The recovery baseline before the documentation/presentation revision recorded 788 passing selected tests, 24/24 corpus gates, 10/10 additional static runs, 41/41 decompilations, and 9/9 benign runtime-oracle matches. These measurements cover different assertions and do not prove every recovered path. Release-preparation checks are recorded separately below.

Known corpus gaps include the Mlfhntkcvb debugger-present reconstruction disagreement, one unrecovered catalogued body in `mc.dll`, substantial residual control flow/runtime infrastructure in large Reactor outputs, and incomplete extraction paths. VM checks can remain inconclusive even when outputs are useful and structurally verified.

Read [support and limitations](https://github.com/jgajek/CILantro/blob/v0.10.0/docs/compatibility.md) before relying on a result. Neither cleaned assemblies nor extracted binaries are made safe to execute by recovery.

## Interface notes

Human CLI wording and layout have changed. Automation should consume `--json`; `cilantro.run/1` and `cilantro.error/1` remain the manifest/error identifiers. CLI reconstruction is enabled by default outside strict mode; MCP reconstruction remains opt-in. Analysis-only writes reports and extracted artifacts but no cleaned assembly.

Archives provide Windows x64 and Linux x64 self-contained CLI/MCP executables, documentation, schemas, licence, and accompanying SHA-256 checksums.

## Release preparation

The release-preparation revision passed the established 791-test local selection, including a concurrent status-polling regression, and checked all local documentation paths. Eleven saved corpus results were rendered for presentation review. Self-contained Windows CLI/MCP builds succeeded. The published Windows CLI passed version, help, ordinary recovery, analysis-only JSON, strict-mode, and JSON-error smoke checks on a benign probe. These checks do not represent a new run of the entire malware corpus. Linux packaging and target execution remain release-CI checks.
