# CILantro 1.0.9

CILantro 1.0.9 improves recovery of erased field and parameter types, preserves constructors required by generic constraints, and reduces full WMS analysis time while retaining the verified cleaned output.

- Restore reference and array signatures through proved field-copy, local and parameter flows, including seeded cycles and generic forwarding. Unknown writers, conflicting types, escaping addresses and unseen callers still refuse the proof.
- Recognize narrowly defined output-only COM SAFEARRAY contracts and resource-manager type identity uses through metadata. These proofs do not invoke COM or execute application code.
- Preserve parameterless constructors needed by surviving generic `new()` constraints and their initialization dependencies. Optional cold-initializer cleanup proof refusals retain the original candidate and record evidence without adding an application recovery blocker.
- Expand configured-host and debugger-variant bounded VM comparisons while retaining original refusals and disagreements. Guard-neutralized comparisons are separately identified and do not replace the original trial result.
- Reduce repeated graph construction, share invocation-local field-use indexes, avoid unused structural description and hash work, and reuse dispatcher analyses only before any body edits.
- Process standalone control-flow completion with at most four independent method workers. Within-method rewrite ordering, proof budgets, verification and rollback remain unchanged; reports publish in original method order.

The WMS managed sample (`9e76d2c69d058e209da12460dba98c5947a6d65b78aec310b69438fad1e8608e`) restores **25,361 method bodies**, **194,451 proxy calls** and all **24,780 protected string sites**. The cleaned assembly has **zero independent ILVerify findings and no unreadable bodies**. Generic construction and callback targets remain retained. This does not establish full GUI/COM runtime equivalence; VM-cache differences, sparse-host refusals and other comparison limits remain recorded.

Two separate serial baseline/candidate measurements reduced full WMS analysis from **29m17s to 25m41s (12.3%)**, then from **27m49s to 24m28s (12.1%)**. Each is one paired observation, with its own fresh baseline, rather than a repeated median or a cumulative speedup claim. Both retained VM reconstruction, renaming, 11 installer libraries, the 256-million-step declaration and recursive child recovery. The performance candidates preserved the verified cleaned DLL byte-for-byte; detailed reports and additional artifacts matched after timing/path normalization. Individual pass timings varied. See [performance measurements](../performance.md) for the scope and methodology.

Validation before the version bump: **3,672 passed, 147 skipped, zero failures** in the full Linux suite; **303 passed, one skipped** in focused Windows checks. The benchmarked production and test sources matched across platforms. After the version bump, checks excluding high-cost tests pass **3,649 tests on Linux** with the intact corpus and **3,600 tests on Windows** with no samples, including version-metadata checks; builds have zero warnings or errors. The release workflow tests each platform build and smoke-tests the native Linux/macOS CLI and MCP executables.
