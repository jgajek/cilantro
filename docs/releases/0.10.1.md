# CILantro 0.10.1

This regular release improves interpreter correctness, resource recovery, and the evidence used to validate reconstructed virtualized methods.

## Changes

- Preserve exception-handler flow during local constant propagation, including nested finally paths.
- Correct reflection over constructed generic methods, parameter and return types, method flags, and overload selection.
- Preserve boxed native-pointer behavior needed by protected loaders.
- Compare original and rebuilt methods using expanded managed-state snapshots, modeled native regions, ordered memory writes, image protections, and network settings. Large byte arrays use bounded full-content hashes.
- Add independent repeat-call trials and configured-host trials. Honor declared interpretation budgets across warm-up and measurement, and retain cold-start disagreements even when repeat calls agree.
- Isolate network settings per interpreter machine.
- Preserve AppDomain event subscription order, remove the last equivalent handler, and resolve resources through the first handler returning an assembly. Assembly resource callbacks receive the requesting assembly identity.

## Validation and limits

Development validation recorded 829 passing selected regression tests. The latest complete corpus run passed 24 gates; after the final resource-event changes, all 11 Reactor 7/ConfuserEx gates and Qbjuef recovery were rerun successfully. Qbjuef structurally verified, with its cleaned root, two cleaned children, and two extracted payloads unchanged. Reactor 6 was not rerun after those final changes. Existing benign runtime-oracle results are historical; no new native runtime-oracle run is claimed for this patch.

Cold-start reconstruction disagreements remain in the documented VM cases. Repeat-call agreement is bounded evidence, not complete equivalence. Registration effects remain incompletely modeled; some VM paths, control-flow obfuscation, protector infrastructure, and extraction-completeness questions remain unresolved.

See [support and limitations](https://github.com/jgajek/CILantro/blob/v0.10.1/docs/compatibility.md) and [VM validation](https://github.com/jgajek/CILantro/blob/v0.10.1/docs/devirtualization.md).
