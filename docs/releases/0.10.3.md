# CILantro 0.10.3

This regular release makes supported protected assemblies substantially easier to inspect, improves late constant recovery, and strengthens the modeling and evidence used for VM reconstruction. Windows x64 and Linux x64 downloads include the self-contained CLI and MCP server.

## Changes

- Unflatten more dispatcher paths using proven stack values, scalar locals, temporary state, arithmetic and comparisons. Incoming facts are used only after analysis converges across joins and loops; address-exposed state and conflicting values remain unknown.
- Specialize successive proven branches while preserving ordered calls, field reads, initialization triggers and exceptions. Fold copied arithmetic and remove dead state writes only where destination and handler observations allow it. Keep this specialization late so it does not obscure earlier recovery patterns.
- Recover more numeric constants from object-backed tables, readonly delegate dependencies, shared lookup trees and bounded self-contained construction. Revisit values exposed by later initialization and control-flow recovery.
- Reconstruct supported dynamically emitted decoding methods into marked ordinary CIL. Improve indexed VM stores, initialization-time observation and the interpretation of reference boxing, unboxing, resolver callbacks and Hashtable keys.
- Preserve required initialization during integer/string recovery and strengthen cold-start, module-initialized and repeat-call comparisons. Expanded state evidence includes application-domain data, delegate subscriptions, native-memory history and alias boundaries; disagreement remains visible.
- Add whole-corpus completion measurement and comparison scripts, and extend the recovery and limitations documentation.

## Measured readability improvements

On the pinned Mlf payload, the final incoming-state change improves the preceding development output as follows. This table is a comparison of the last two development builds, not a direct 0.10.2-to-0.10.3 benchmark.

| Metric | Before | 0.10.3 recovery implementation |
| --- | ---: | ---: |
| IL switches | 74 | 23 |
| Decompiled `goto`s | 617 | 438 |
| Decompiled `while` loops | 164 | 74 |
| Non-no-op IL instructions | 38,175 | 37,456 |
| Decompiled source lines | 19,399 | 18,064 |

The output restores all 700 numeric-table constants and 172 strings, reads 4,854 VM operations and walks 4,846, removes 561 runtime types, and passes structural verification and ILSpy decompilation. Calls needed for initialization remain. Some switches are necessary input-dependent choices, not protector routing.

## Validation and remaining gaps

The final pre-release recovery build passed **1,208 selected regression tests** and **24/24 standard corpus gates**: 13 Reactor 6, nine Reactor 7.5 and two ConfuserEx. All **25 standard assembly reports**, **nine reports from four additional recursive inputs**, and **46 saved-output pass trials** verified structurally. Matched fresh corpus runs preserved recovered coverage and extracted payload hashes. Generated benign CLR fixtures check ordered effects, arithmetic faults, joins, loops, aliases and exception-visible state. Malware corpus trials use static interpretation and decompilation only. Public CI runs the available suite and reports private-sample skips separately.

Full unprotection remains incomplete. WindowsManagement's managed stage retains 179 dispatcher-shaped methods; `mc.dll` retains 26, and the full Reactor 7.5 fixtures retain three per framework. These are heuristic candidates, including ordinary library logic. Unsupported VM paths and full-state reconstruction disagreements remain.

The Mlf default run retains 23 switches in 16 methods. Its unreachable residue increases from 362 to 672 instructions under the current exception-boundary continuation policy, despite the overall size and readability improvement. Its 561 removed runtime types remain below the older separate reconstruction cleanup gate's expectation of 564; the passing standard corpus gates disable reconstruction and do not supersede that gate. Structural validity, readable output and bounded comparison agreement are not universal behavioral equivalence.
