# CILantro 1.0.0 preparation

Source metadata targets 1.0.0. This document records preparation, not a published release or a new corpus-completion verdict.

## Analyst experience

- The README uses the Flow mark: cilantro leaves with branching recovery paths.
- Human CLI runs start with a Reveal-inspired nested-C text banner and the tool version.
- Live output names each target, analysis phase and pass. Pass outcomes distinguish successful, partial, unsupported, failed and skipped work, with change counts and elapsed time.
- Native-wrapper unpacking and recursively recovered children appear in the same transcript. Pass counters restart per managed input.
- The result summary points to the recommended assembly, offline HTML report and artifact inventory while keeping review items and validation limits visible.
- Interactive terminals use green results, cyan progress and artifact paths, amber review items, and red failures. `--no-color`, `NO_COLOR`, `TERM=dumb` and redirected output disable colors. Text graphics use ASCII characters.
- `--json` remains one run/error object without a banner or progress. `--version` remains a bare version. MCP does not receive console output from the core progress observer.

## Validation before publication

Use the [release checklist](../development.md#release-checklist), including both packaged platforms, full tests, private-sample skips, frozen-corpus gates and benign probe trials. Recheck default, strict, analysis-only, partial, wrapper, embedded-child, redirected, verbose and JSON/error paths.

The [0.10.6 notes](0.10.6.md) and [corpus status](../status-report.md) remain the measured recovery baseline. Existing corpus counts do not establish coverage or behavioral equivalence for a newly built binary. Record 1.0.0 validation evidence before tagging and publishing.
