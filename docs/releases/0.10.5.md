# CILantro 0.10.5

This regular release improves recovered application control flow, completing the identified dispatcher and opaque-guard cleanup in the frozen intact managed corpus while preserving application switches. Windows x64 and Linux x64 downloads include the self-contained CLI and MCP server.

## Changes

- Fold stack-carried constant selectors only when incoming paths agree. Specialize proven dispatcher edges while preserving unknown application selectors, state stores and evaluation effects.
- Recover longer effectful dispatcher paths and consume constant helpers exposed by late recovery without discarding initialization triggers or exceptions.
- Repair backward stack handoffs and exclusive exception-region ends exposed by unreachable-code removal. Rewrites retain verification and rollback checks.
- Remove a reconstructed Reactor integer guard pool after checking its literal initialization, confined construction and direct consumers. Preserve initialization and recursive-entry exceptions through a small helper, and remove redundant checks only on proven normal-flow paths.
- Physically remove the pool's obsolete integer fields and assignments. Reject aliases, additional writers, explicit reflective references and unexplained reachable numeric-token consumers. Leave general reflective-write safety rules unchanged; `--keep-runtime` disables this guard-pool cleanup.
- Update the corpus status report and add regression coverage for application switches, initialization failures, recursive entry, exception handlers and unsafe pool uses.

## Validation and scope

The control-flow sweep covers **83 intact managed outputs** from the frozen **85-hash baseline**. The native bootstrap is represented by its recovered managed stage; the previously accepted damaged NETReactorSlayer Lqcuzgc exclusion remains explicit.

- Remove **2,724 switches** from protector control flow while retaining all **933 reviewed application switches**.
- Remove **62,470 opaque guard reads across 15,918 methods** and **100 protector integer fields** from the native managed stage. This guard-completion round removes another **76,469 CIL instructions**. The other 82 outputs are byte-identical to the preceding dispatcher sweep.
- Preserve all **65,008 original method identities**, retained resource bytes and entry points, with no increase in per-method stack diagnostics. Declare the one added initialization helper and removed fields to structural verification.
- Pass **83 strict writes and preservation checks**, repeated cleanup checks on all 83 outputs, and **14/14 VM-removal checks**. The changed native stage decompiles successfully; prior decompilation and benign runtime evidence for unchanged outputs remains bound to their hashes.
- Pass **81 focused tests**, including **19 guard-completion cases**, and **1,295 selected regression tests** in the recovery validation. The release workflow additionally runs the complete sample-independent suite on Linux before publishing either archive.

The preservation contract allows deliberate removal of identified protector metadata. **Computed reflection over the removed protector pool is not preserved or claimed impossible.** Initialization effects and exceptions remain; this is not a general immutable-field assumption.

This release does **not** claim removal of every Reactor artifact or protection. Exhaustive extraction, native-code deprotection, further cleanup/readability work and a refreshed end-to-end root matrix remain separate obligations. The 29-sample Vault inventory was not refreshed. Malware validation uses static interpretation, metadata inspection and decompilation; no malware was executed in the host CLR.

See the [status report](https://github.com/jgajek/CILantro/blob/v0.10.5/docs/status-report.md) for the evidence and remaining gaps.
