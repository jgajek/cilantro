# CILantro 1.0.8

CILantro 1.0.8 fixes VM reconstruction that could discard reflective static-field writes and improves recovery of version-dependent initialization.

- VM observation records actual static-field writes, including `FieldInfo.SetValue` and repeated writes of an unchanged value. An operation that consumes a value and writes it outside the VM is no longer mistaken for a discard.
- Reflective static-field reads and writes initialize the declaring type, preserving cold-start ordering when reconstructed as ordinary field access.
- `Application.ExecutablePath` and `FileVersionInfo.GetVersionInfo` are modeled from the registered input path and PE version resource. Foreign paths, malformed resources and unsupported language selection are refused; analysis does not read arbitrary host files or substitute the host runtime's version.
- Synthetic VM-probe failures remain in reading diagnostics and observation evidence without becoming application blockers. Actual loader-initialization failures remain blockers.
- When MCP callers supply `reportDir`, the default cleaned assembly is written there. An explicit `output` still takes precedence, supporting read-only sample mounts.

The WMS managed sample (`9e76d2c69d058e209da12460dba98c5947a6d65b78aec310b69438fad1e8608e`) completed all 136 pass decisions in **37m16s**, with structural verification passing. It restored **25,361 method bodies**, **194,451 proxy calls** and all **24,780 protected string sites**. The final initializer retains all **108 static-field assignments**, replacing the incorrect single-return body. The 54 application-field differences are gone: eight completed bounded application comparisons matched; seven fixtures remained inconclusive.

That local run enabled VM reconstruction, retained names, supplied 11 matching installer libraries and used a 256-million-step declaration. Its timing is not an isolated benchmark. The full-state verdict still records 13 differing VM-cache roots, all removed from the final assembly. An early optional cleanup-proof budget warning remains recorded, and independent ILVerify findings are unchanged from the previous cleaned assembly. These checks do not establish full IL verifiability or equivalence for arbitrary runtime inputs.

Validation covered 3,511 enabled tests through the full corpus run and a corrected cleanup-order regression rerun, with 147 sample/platform-dependent skips. Focused tests cover reflective initialization, reflective VM writes, image-version parsing, synthetic-probe diagnostics and both MCP execution modes. Release builds complete without warnings or errors.
